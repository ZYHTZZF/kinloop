- **状态**: 待实现

- **更新时间**: 2026-04-05

---

## 1. 产品概述

### 1.1 产品定义
Kinloop 聊天系统是一款家庭沟通平台，分为两端：
- **子女端**：近似微信的成熟社交体验（现代化、丰富功能）
- **老人端**：极简设计（大字体、大按钮、易操作）

### 1.2 核心能力
- ✅ 实时文字消息（一对一）
- ✅ 语音通话（一对一 P2P）
- ✅ 视频通话（一对一 P2P）
- ✅ 本地永久存储（不删除）
- ✅ 离线推送通知
- ✅ 弱网自动降质
- ✅ 同机多端测试支持

## 2. 需求规格

### 2.1 消息功能

#### 2.1.1 消息类型
| 类型 | 子女端 | 老人端 | 说明 |
|------|-------|-------|------|
| 文字 | ✅ | ✅ | 支持任意长度 |
| 图片 | ✅ | ✅ | 预览、点击查看大图 |
| 语音消息 | ✅ | ✅ | 按住录音，松开发送 |
| 文件 | ✅ | ❌ | 暂不支持 |
| 链接预览 | ✅ | ❌ | 暂不支持 |
| 表情 | ✅ | ❌ | 暂不支持 |

#### 2.1.2 消息状态
- **发送中** - Sending
- **已发送** - Sent
- **已传达** - Delivered
- **已读** - Read

#### 2.1.3 消息存储
- **存储位置**: IndexedDB（客户端离线存储）
- **存储策略**: 永久保留，不自动删除
- **备份**：可选通过服务器同步（实现时暂不做）
- **检索**：支持时间范围查询、关键词搜索

### 2.2 聊天列表页

#### 2.2.1 子女端（FamilyChatList）
```
[用户A]  最后一条消息预览...  14:32  [2]  ❌
[用户B]  让我看看      13:45  [0]
[用户C]  好的          10:20
```
- **功能**:
  - 显示所有对话（按最后消息时间排序）
  - 显示未读数/红点
  - 下拉刷新，快速拨号
  - 长按/滑动删除（逻辑删除）

#### 2.2.2 老人端（ElderChatList - 简化）
```
[妈妈]   打电话给我吧

[女儿]   早上好

[儿子]   你好
```
- **功能**:
  - 超大字体、超大头像
  - 2-3 个主要联系人
  - 快捷语音/视频按钮
  - 最少化交互

### 2.3 聊天详情页

#### 2.3.1 子女端（FamilyChatDetail）
```
┌─────────────────────┐
│ 张三          📞📹  │  <- 头部：名字+快捷通话
├─────────────────────┤
│ [14:32] 你好吗?     │
│         已读        │
│       [我] 很好      │  <- 消息气泡（左右对齐）
│              15:00  │
│         已读        │
│                    │
├─────────────────────┤
│ [+][😊][🔊] [文字框] │  <- 输入区（4 个按钮）
│         [发送]      │
└─────────────────────┘
```

- **消息气泡设计**:
  - 左对齐 = 对方消息（灰色背景）
  - 右对齐 = 我的消息（蓝色背景）
  - 头像 + 时间 + 已读状态
  - 长按消息：转发、编辑、删除

- **输入框按钮**:
  - `+` 图片/文件选择
  - `😊` 表情选择器
  - `🔊` 语音消息（按住录音）
  - 文字输入框（自动换行）
  - 发送按钮（或 Enter）

- **交互**:
  - 输入自动滚动到底部
  - 接收消息自动滚动到底部
  - 长按气泡显示菜单

#### 2.3.2 老人端（ElderChatDetail - 简化）

│  [你好吗?]  [发送]     │  <- 文字输入（预设快捷语）

- **消息气泡**:
  - 超大字体（18px+）
  - 简化的左右对齐

- **快捷区**:

- **预设快捷语**:
  - "好的" "你好" "再见" 等

### 2.4 语音通话

#### 2.4.1 发起流程
1. 点击聊天页面 📞 按钮
2. 建立 Signaling 连接
3. 对方收到来电通知（弹窗/推送）
4. 对方接听 → WebRTC P2P 建立
5. 开始音频传输

#### 2.4.2 通话界面（子女端）
```
┌──────────────────────┐
│  张三        05:32   │  <- 名字 + 通话时长
├──────────────────────┤
│                      │
│    [大头像]          │
│                      │
├──────────────────────┤
│  [麦克风] [扬声器]    │
│  [📹切换] [挂断❌]    │  <- 4 个按钮
└──────────────────────┘
```

#### 2.4.3 通话界面（老人端 - 简化）
```
┌────────────────────────┐
│      妈妈              │
│     通话中...  05:32  │
├────────────────────────┤
│         🎤             │
│      (大头像)          │
├────────────────────────┤
│    [🔇转向扬声器] [❌挂断]│
└────────────────────────┘
```

#### 2.4.4 状态流转
```
Ringing (对方响铃) 
  → Answered (已接听)
  → Connected (已连接)
  → Ended (已挂断)
```

### 2.5 视频通话

#### 2.5.1 发起流程
1. 点击聊天页面 📹 按钮
2. 建立 Signaling + WebRTC
3. 获取摄像头权限
4. 对方收到视频来电
5. 对方接听 → 双向视频/音频建立

#### 2.5.2 通话界面（子女端）
```
┌────────────────────────────┐
│  [远程视频窗口 (80%)]      │
│  ┌──────────────────────┐ │
│  │                      │ │
│  │    对方的视频        │ │
│  │                      │ │
│  │  [我的小窗 (20%)]   │ │
│  │  ┌─────────────┐   │ │
│  │  │  我的视频   │   │ │
│  │  └─────────────┘   │ │
│  └──────────────────────┘ │
├────────────────────────────┤
│ [麦克] [摄像] [切换] [挂断❌] │
└────────────────────────────┘
```

#### 2.5.3 通话界面（老人端 - 简化）
```
┌──────────────────────────┐
│  [对方视频 (95%)]        │
│  ┌────────────────────┐ │
│  │                    │ │
│  │   妈妈的视频       │ │
│  │                    │ │
│  │   [我 (小窗)]     │ │
│  └────────────────────┘ │
├──────────────────────────┤
│    [🔇]        [❌挂断]   │
└──────────────────────────┘
```

#### 2.5.4 网络适应
- **强网**: 1080p/30fps
- **中网**: 720p/30fps
- **弱网**: 360p/15fps（自动降质）

### 2.6 推送通知

#### 2.6.1 通知类型
| 事件 | 内容 | 优先级 |
|------|------|--------|
| 新消息 | "张三: 你好" | Normal |
| 来电呼叫 | "张三 来电..." | High |
| 视频呼叫 | "张三 视频通话..." | High |
| 离线消息 | "你有 3 条未读消息" | Normal |

#### 2.6.2 通知渠道
- **离线状态**: Web Push API
- **应用内**: Toast/横幅
- **声音**: 可选开启/关闭
- **震动**: 可选开启/关闭

### 2.7 弱网降质策略

#### 2.7.1 检测机制
- 监测 RTCPeerConnection 的 `getStats()` 
- 计算丢包率、延迟、带宽

#### 2.7.2 自适应处理
```
丢包率 < 2% && 延迟 < 100ms → 保持高质量
丢包率 2-5% || 延迟 100-300ms → 降至中质量
丢包率 > 5% || 延迟 > 300ms → 降至低质量
```

#### 2.7.3 具体调整
- **分辨率**: 1080p → 720p → 360p
- **帧率**: 30fps → 25fps → 15fps
- **码率**: 自动调参

## 3. 技术规格

### 3.1 前端技术栈
- **框架**: React 18 + TypeScript
- **状态管理**: 可选（简单使用 Context）
- **实时通信**:
  - WebSocket (订阅/发布消息)
  - WebRTC (P2P 音视频)
- **本地存储**: IndexedDB (离线缓存)
- **通知**: Web Notifications API
- **音视频**:
  - getUserMedia() 获取设备
  - RTCPeerConnection 建立连接
  - simple-peer 封装（可选）

### 3.2 后端需求（已有）
- **WebSocket 服务** - 消息/ Signaling
- **消息队列** - 离线消息存储
- **用户在线状态** - 实时更新

### 3.3 信令协议

#### 3.3.1 消息发送
```json
{
  "type": "message",
  "from": "user_a",
  "to": "user_b",
  "content": "Hello",
  "timestamp": 1680000000000,
  "messageId": "uuid"
}
```

#### 3.3.2 通话发起
```json
{
  "type": "call",
  "callType": "voice|video",
  "from": "user_a",
  "to": "user_b",
  "offer": { /* SDP Offer */ }
}
```

#### 3.3.3 通话应答
```json
{
  "type": "answer",
  "from": "user_b",
  "to": "user_a",
  "answer": { /* SDP Answer */ }
}
```

#### 3.3.4 ICE Candidate
```json
{
  "type": "ice-candidate",
  "from": "user_a",
  "to": "user_b",
  "candidate": { /* RTCIceCandidate */ }
}
```

## 4. 用户场景

### 4.1 场景 1：子女给父母发消息
```
1. 子女打开 FamilyChatsPage
2. 选择父/母聊天窗口
3. 输入文字消息
4. 点发送
5. 消息立即显示（右对齐）
6. 消息状态：Sending → Sent → Delivered → Read
7. 父母端：收到推送，打开 ElderChatList，看到新消息
```

### 4.2 场景 2：父母视频通话子女
```
1. 老人打开 ElderChatList
2. 找到"女儿"，点击 📹 (视频)
3. 系统请求摄像头权限
4. 显示 "呼叫中..." 界面
5. 子女端收到通知 "妈妈 视频通话"
6. 子女点接听
7. 双方看到对方视频，开始通话
8. 弱网时自动降质
9. 挂断后，记录保存
```

### 4.3 场景 3：离线消息
```
1. 用户A 向用户B 发消息
2. 用户B 离线（无 WebSocket 连接）
3. 消息保存在服务端消息队列
4. 用户B 推送通知出现
5. 用户B 上线后立即拉取离线消息
6. 本地 IndexedDB 更新
```

## 5. 非功能需求

### 5.1 性能指标
| 指标 | 目标 |
|------|------|
| 消息发送延迟 | < 100ms |
| 消息接收延迟 | < 100ms |
| 通话建立时间 | < 3s |
| 视频首帧延迟 | < 2s |
| 应用启动时间 | < 2s |

### 5.2 可靠性
- 消息不丢失（本地 + 服务端双备份）
- 通话断线自动重连
- 高延迟自动降质
- 通话异常优雅关闭

### 5.3 设备支持
- **浏览器**: Chrome/Edge/Safari (WebRTC 支持)
- **OS**: Windows/macOS/Linux/iOS/Android
- **测试**:
  - 同一台电脑（虚拟摄像头/多标签页）
  - 不同设备（同 LAN 或互联网）

### 5.4 用户体验
| 方面 | 要求 |
|------|------|
| 响应感 | 所有操作 < 200ms 反馈 |
| 无障碍 | WCAG 2.1 AA 级（重点老人端） |
| 易用性 | 老人端超高优先级 |
| 一致性 | 复用现有设计系统 |

## 8. 风险与限制

### 8.1 已知限制
- ❌ 暂不支持群聊
- ❌ 暂不支持消息加密（传输通过 HTTPS/WSS）
- ❌ 暂不支持文件传输（仅图片）
- ❌ 同机测试须用浏览器标签页/多窗口
- ❌ 视频质量依赖网络实际带宽

### 8.2 风险
| 风险 | 缓解策略 |
|------|---------|
| WebRTC 浏览器兼容性 | 使用 webrtc-adapter，测试主流浏览器 |
| NAT 穿越失败 | 配置 TURN 服务器（可选） |
| 用户权限拒绝 | 友好的权限申请流程提示 |
| 消息存储爆炸 | 监控 IndexedDB 大小，手动清理选项 |
